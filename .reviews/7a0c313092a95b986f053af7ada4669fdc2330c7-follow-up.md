# Follow-up review of `7a0c313092a95b986f053af7ada4669fdc2330c7`

- **[P2] Model operation start separately from its result** — `spec/KeyInventory.tla` (`ExecuteSucceeded`, `ExecuteUnknown`, `StartedOnlyBeforeDeadline`). The specification says the confirmation deadline prevents the key store from **starting** an operation after the deadline. The model treats starting, physically carrying out the operation, and appending its result as one atomic transition, then checks that the `succeeded` or `unknown` result event precedes `deadline-passed`. This rejects a legal execution where the key store starts before the deadline, the deadline passes while the operation is in flight, and the result is appended afterward. Add an explicit started/in-flight state and gate only the start transition on the deadline; allow an already-started operation to finish and record its result after the deadline. Check both interleavings: deadline before start must prevent the operation, while start before deadline may complete afterward.
